## Проверяемые сценарии

- Все существовавшие core contract tests выполняются для memory и SQLite.
- Ошибка/panic/cancellation callback откатывает message и state; даже проигнорированная ошибка core decision не допускает partial commit.
- Конфликт второго scope откатывает первую reservation и новую attempt; duplicate lease не оставляет запись.
- Два независимых SQLite handles конкурируют за одну revision; проходит один writer.
- Verification/evidence/message/state/attempt/reservation изменяются атомарно; late error откатывает весь результат.
- Close/reopen сохраняет unknown outcome, ownership, reservations, dedup и полный evidence/verification graph. Collision после reopen отклоняется.
- Отдельный дочерний процесс завершает работу без Close внутри transaction: ранее committed task сохраняется, uncommitted task отсутствует.
- Пустая v0 → v1; неудачная initial migration и неудачная v1 → synthetic v2 откатывают schema/data/history/version.
- Future version, изменённая/неполная история и unrelated DB отклоняются; старый открытый handle также прекращает writes после смены schema version.
- Foreign keys и физический SQL CAS; FULL/foreign keys/busy timeout на четырёх соединениях; WAL/incremental vacuum фактически прочитаны через PRAGMA.
- Lock wait ограничен context/configured budget; stale ownership, запрет unsafe ready и исчерпание revision/generation покрыты regression tests.
