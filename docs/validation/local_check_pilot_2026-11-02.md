## Реализация

`cmd/acp`: prepare/check/status/recover/gc, версия 0.1.0-pilot. `internal/localcheck` адаптирует одну явно выбранную доверенную программу к существующему Runner. Config не поступает из Job/модели. До запуска проверяются размер/структура профиля, точные входные хеши и executable. Prepare только создаёт новый профиль для точных байтов или доказанного CRLF/LF-эквивалента, не выполняет программу и отказывает при другом изменении исходников/существующем output. Операция проверки считается mutation и резервирует workspace в одной БД. Ведутся прежние Task/Operation/Attempt/Evidence и SQLite v3 без миграций.

Наблюдённое завершение процесса, временный вывод и снимок связываются с квитанцией; после её сохранения и чтения controller actor применяет verification и FinalizeTask. Ненулевой обычный exit — известная неуспешная проверка. Timeout/cancel/overflow/неизвестный COMMIT не дают автоматического повтора. Повтор существующей Task не вызывает программу. Recover принимает только уже reported-состояние с совпадающими намерением, worker_report и квитанцией. Пропажа/подмена артефакта не восстанавливает результат по хешу.

Raw output и пути/argv не сохраняются в canonical records. Вывод доступен только по явному местному --show-output, не более 64 KiB; в отчёт/репозиторий полного лога нет. Квитанции ограничены 4 KiB, terminal state подчиняется R3, очистка конечная и явная. Контекст процесса не наследует credentials/proxy/HOME/PYTHONPATH; сохраняются только SYSTEMROOT/WINDIR/TEMP/TMP/PATH и фиксированные настройки Python UTF-8/bytecode. Это не изоляция недоверенной программы и не доказательство остановки дерева процессов.

Сборки для выдачи содержат версию пилота и исходный commit; это пробные executables, не управляемая установка и не отдельный production release.

Нет рабочего model/agent adapter, удалённого запуска, VPS/deploy, фоновой очереди, расписания, ScopedKB runtime или автоматического исправления проекта. Программа имеет права пользователя ОС и должна быть доверенной; профиль и inputs не являются sandbox. Хранение state требует приватного локального каталога, а на Windows — соответствующих ACL. Потерянный непосредственный процесс или его потомки не объявляются безопасно прекращёнными без отдельного evidence.
